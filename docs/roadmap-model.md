# План: модель смысла и правила

Итог обсуждений 29 сентября 2026. Что решили делать после единого пути (контекст внутри поиска, одна функция `decode`) и пакета грамматики.

## 1. Двухуровневая схема: пары лемм и грамматика форм

Сейчас модель контекста (`bigrams.fst`) — отдельный автомат. Пары в нём записаны буквами целиком, по формам: 685 тыс. пар.

Раскладка: P(слово₂ | слово₁) ≈ P(лемма₂ | лемма₁) × P(форма₂ | лемма₂, грамматика).
- **Смысл** («пить → чай») хранится парами лемм. Их в разы меньше, чем пар форм, и они обобщаются на невиданные сочетания форм.
- **Форму** («чаю» или «чай») выбирает грамматика: рамки, согласование, управление. Она уже есть.
- **Пары форм** остаются только там, где грамматика их не объясняет: «в течение», «на днях».

«Паутина» ссылок. У каждой леммы номер, он хранится в значении словаря рядом с частотой и грамматикой (одна структура). Пары — отсортированные списки номеров лемм с плотным кодированием. Номера идут в лексикографическом порядке, поэтому каждый узел словаря покрывает непрерывный отрезок номеров. Нижняя граница цены префикса в поиске — это запрос максимума на отрезке, и контекст остаётся внутри поиска.

Единица смысла — лемма, а не корень. Лемма убирает словоизменение, но сохраняет словообразование: «охуенный» и «охуевший», «пиздатый» и «пиздец» — разные леммы, у каждой свой смысл. Корни годятся для сжатия написания, не для смысла.

## 2. Эмбеддинги лемм

Классы смысла сейчас: PPMI по предложениям → SVD → 512 групп, у слова один номер. Это грубо сжатый эмбеддинг. Лучше хранить короткий вектор на лемму: 16–64 числа по байту, 100 тыс. лемм — 1,6–6 МБ. Сходство станет плавным.

Два сигнала, оба нужны:
- **пары соседних слов** — порядок, устойчивые сочетания;
- **совместная встречаемость в предложении** — тема.

Граф лемм с рёбрами по силе связи (PMI) содержит всю информацию, эмбеддинг — его сжатие. Оптимум по замеру «точность на байт»: явные рёбра для сильных связей плюс короткие векторы для остального.

Ограничения:
- антонимы («хорошо» и «плохо») по встречаемости близки — для подсказки слова это не беда;
- многозначность внутри леммы («ключ») различает контекст.

## 3. Маленький трансформер: откалиброванный «выбирающий»

Поверх векторов лемм: 2–4 слоя шириной 64–128, сотни килобайт. Векторы входа и выхода общие.
- **Задача:** не порождать следующее слово, а **выбрать среди кандидатов нашего поиска** с калиброванной уверенностью. Идея Jev (TypeSafe AI): типизированный выбор из заданного набора, вероятности вместо текста. Калибровка критична: все наши решения — пороги (запятая при 90%, запас для замены настоящего слова).
- **Оценка кандидата:** вектор контекста h · вектор леммы кандидата (близко к JEPA — сравнение в пространстве представлений) плюс грамматика формы. Считаются только найденные кандидаты, выходной слой на весь словарь не нужен.
- **Обучение на синтетике.** `typetext` и `swipesim` порождают тройки «контекст + кандидаты декодера + что человек имел в виду» на любом корпусе и при любом шуме нажатий или свайпа. Учится офлайн, на пользователе ничего не учится.
- **Место в поиске:** пересчёт найденных кандидатов (с запасом). Граница отсечения внутри поиска остаётся от пар лемм.
- **На телефоне:** вывод на Rust, несколько матричных умножений, доли–единицы миллисекунд на место. Для набора слово за словом подходят и рекуррентные схемы (RWKV, Mamba): состояние обновляется на каждое новое слово.

Порядок: лемматизация корпуса → векторы лемм → двухуровневая схема (замер) → трансформер-выбирающий (замер против неё).

Трансформер не заменяет двухуровневую схему, это два слоя разной скорости («быстрое и медленное мышление»):
- **пары лемм** работают внутри поиска: быстрая оценка с нижней границей на префикс, без неё нечем отсекать;
- **трансформер** точно выбирает из короткого списка, который поиск нашёл.

Векторы лемм у них общие, форму слова в обоих случаях выбирает грамматика.

## 4. Корпуса

Веб систематически ошибается ровно в тех правилах, которые мы учим:
- «в течении», «не смотря на»;
- «тем не менее,» (71% веба);
- «подскажите пожалуйста» без запятых (51%);
- «по окончанию» (27% даже в новостях).

Правила, запятые и пары-путаницы нужно учить на вычитанных текстах (Leipzig news, книги, основной корпус НКРЯ), а где ошибается и корпус — задавать закрытыми списками.

## 6. Свайп на реальных жестах

Проверочная часть Yandex Cup 2023 (10 тыс. жестов), только для замеров. Данные вне репозитория, на них ничего не учится и не подбирается. Наша геометрия без контекста: 69,1% верных с первого места, у нейросети CleverKeys 85%.
- 19% слов теряются жёсткими геометрическими отсечками: радиус вокруг пути, начало и конец жеста.
- Следующий шаг: единый путь для геометрии — отсечка превращается в стоимость, и контекст может вытащить слово.
- Дальше: опорные точки на концах, штраф за направление, компенсация углов и быстрого старта. Проверка: подбор на одной половине набора, итог на другой.
- Если разрыв останется большим — маленький нейрокодировщик жеста (вероятности букв по кадрам) в наш обход словаря.

## 7. Дальше

- **Голосовой ввод** — ещё один вид свидетельства: маленькая акустическая модель даёт вероятности фонем, слой произношения (оглушение, аканье, непроизносимые) ведёт к буквам, дальше тот же `decode` с контекстом, грамматикой и запятыми.
- **Настройка `MADV_RANDOM`** для словарей (без упреждающего чтения) — с замером экономии памяти.
