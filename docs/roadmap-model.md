# План: модель смысла и правила

Итог обсуждений 29 сентября 2026. Что решили делать после единого пути (контекст внутри поиска, одна функция `decode`) и пакета грамматики.

## 1. Двухуровневая схема: пары лемм и грамматика форм

Сейчас модель контекста (`bigrams.fst`) — отдельный автомат. Пары в нём записаны буквами целиком, по формам: 685 тыс. пар.

Раскладка: P(слово₂ | слово₁) ≈ P(лемма₂ | лемма₁) × P(форма₂ | лемма₂, грамматика).
- **Смысл** («пить → чай») хранится парами лемм. Их в разы меньше, чем пар форм, и они обобщаются на невиданные сочетания форм.
- **Форму** («чаю» или «чай») выбирает грамматика: рамки, согласование, управление. Она уже есть.
- **Пары форм** остаются только там, где грамматика их не объясняет: «в течение», «на днях».

Словарь «основа + парадигма» — возможный следующий шаг после замера векторов лемм. Узел основы и есть лемма, дальше по переходам идут окончания её парадигмы, как в OpenCorpora и pymorphy. Что это даёт:
- номер леммы, её векторы и грамматика формы берутся из пути по мере набора;
- граница для отсечения точна уже на основе;
- обратный ход «лемма → формы» (кандидаты для предсказания) бесплатный.

Частота формы тогда раскладывается: P(форма) = P(лемма) × P(клетка парадигмы | лемма), то есть двухуровневая схема и для униграмм. Пока номер леммы лежит в модели контекста (`0, 25, слово`). Хранить его в значении словаря дороже: класс смысла там стоил 3,1 МБ против 0,6 МБ отдельно, потому что частота формы разбивает общие окончания.

«Паутина» ссылок. У каждой леммы номер; структура хранит номер, номер указывает на строку таблицы векторов (`lemmas.bin`, плоский массив: вектор — это случайные байты, FST их не сжимает). Явные пары — отсортированные списки номеров лемм с плотным кодированием. Номера идут в лексикографическом порядке, поэтому каждый узел словаря покрывает непрерывный отрезок номеров. Нижняя граница цены префикса в поиске — это запрос максимума на отрезке, и контекст остаётся внутри поиска.

Единица смысла — лемма, а не корень. Лемма убирает словоизменение, но сохраняет словообразование: «охуенный» и «охуевший», «пиздатый» и «пиздец» — разные леммы, у каждой свой смысл. Корни годятся для сжатия написания, не для смысла.

Верхний список как граница (по мотивам Gboard 2024, [arXiv 2410.15575](https://arxiv.org/abs/2410.15575)). У них нейросеть после каждого слова даёт 1–5 тыс. лучших слов, они становятся дугами FST, а остальные слова получают униграмму — приближение без границы. У нас: верхние N лемм для контекста посчитаны точно, а N-я оценка — честная граница для всех остальных, намного теснее общего максимума. Те же N лемм — кандидаты предсказания. Их LSTM на 6,4 млн параметров стоила +17–28% задержки на телефоне при −0,3…−1,2% слов, исправленных пользователем.

## 2. Эмбеддинги лемм

Классы смысла сейчас: PPMI по предложениям → SVD → 512 групп, у слова один номер. Это грубо сжатый эмбеддинг. Лучше хранить короткий вектор на лемму: 16–64 числа по байту, 100 тыс. лемм — 1,6–6 МБ. Сходство станет плавным.

Два сигнала, оба нужны:
- **пары соседних слов** — порядок, устойчивые сочетания;
- **совместная встречаемость в предложении** — тема.

Граф лемм с рёбрами по силе связи (PMI) содержит всю информацию, эмбеддинг — его сжатие. Оптимум по замеру «точность на байт»: явные рёбра для сильных связей плюс короткие векторы для остального.

**Сделано (30 сентября 2026): пары соседних лемм.** `tools/lemma_corpus.py` → `tools/lemma_vectors.py` → `tools/lemma_export.py`, в движке `kbcore::lemmas`. Модель P(лемма₂ | лемма₁) = softmax(u·v + b) по 50 тыс. лемм (98% слов текста), полный softmax, вероятности калиброваны. Корпус: Leipzig (новости, Википедия, веб) и Tatoeba, 36 млн слов, каждое 50-е предложение отложено.

Отложенный текст, бит на слово:

| модель | бит | top-1 | top-10 | размер |
|---|---|---|---|---|
| униграмма | 11,02 | 3,9% | 17,1% | — |
| векторы, 16 чисел | 9,58 | 9,2% | 27,2% | 1,7 МБ |
| векторы, 32 числа | 9,42 | 9,4% | 28,6% | 3,3 МБ |
| 32 + 100 тыс. явных пар | 9,32 | | | +0,4 МБ |
| все пары лемм (Кнезер–Ней) | 9,17 | 10,1% | 30,4% | 26 МБ |

В клавиатуре — PMI лемм на собственную вероятность формы (`w_lemma` 0,5), честная граница в поиске, кандидаты предсказания из верхних 16 лемм (обратный ход по основе). `tools/eval_phrase.py`, 600 предложений:

| | без лемм | 16 чисел | 32 числа |
|---|---|---|---|
| верных слов, неточные нажатия | 93,47% | 93,75% | 93,84% |
| изменено при аккуратном наборе | 2 | 0 | 1 |
| предсказание, где грамматика молчит: top-1 / top-3 | 17,4 / 26,0% | 17,9 / 28,2% | 17,7 / 28,3% |
| свайп σ0,3 | 95,43% | 95,42% (вес 1) | — |

Вес 1 хуже (93,50%, грамматика проседает): смысл перебивает падеж. Взяты 16 чисел: разница с 32 в пределах шума. Размер: `lemmas.bin` 3,2 МБ и номера лемм в модели контекста +0,7 МБ; служебные числа (по 4 байта) можно ужать вдвое.

Ограничения:
- антонимы («хорошо» и «плохо») по встречаемости близки — для подсказки слова это не беда;
- многозначность внутри леммы («ключ») различает контекст.

Смысл от главного слова, а не только от соседа. В «пить горячий ч…» соседнее «горячий» почти ничего не говорит о «чай», а главное слово «пить» — говорит. Грамматика уже находит главное слово через прилагательные («дал книгу другу»). Вторая таблица векторов, выученная на парах «главное → зависимое» (глагол → дополнение, предлог → существительное; пары вытаскивает из корпуса та же грамматика), даст смысловую оценку и от него. Падеж по-прежнему выбирает грамматика, векторы — какое слово по смыслу.

## 3. Маленький трансформер: откалиброванный «выбирающий»

**Сделано (30 сентября 2026): выбирающий в клавиатуре** (`kbcore::chooser`, `tools/chooser.py`, 289 тыс. параметров, 1,16 МБ). Он добавляет к цене движка поправку −f/τ во всех взвешиваниях: набранные, дописанные и нарисованные слова, предсказания (четвёртый признак — «ожидаемое, а не набранное»). Окно из двух слов работает без него. Учился на 1,07 млн слов, набранных через всю клавиатуру с шумом и аккуратно, без её самой (`w_chooser=0`). Замер `tools/eval_phrase.py` и `tools/eval_rules.py`, без него → с ним:
- верных слов при неточных нажатиях 93,74 → 94,39%, изменений аккуратного набора 0 → 0;
- следующее слово, где говорит грамматика: top-1 8,4 → 10,4%, top-3 14,6 → 17,0%; где молчит: 17,9 → 20,8% / 28,3 → 32,6%;
- -тся 74,3 → 78,3%, согласование 63,3 → 65,2%, дефисы 95,3 → 97,7%, ё 99,1%; предлоги 63 → 59%. Причина оказалась не в выбирающем и не в векторах лемм: окно из двух слов теряло пару «со» к «с», если поиск находил её сам как опечатку; исправлено — 83%.
- Скорость: граница в поиске по умолчанию выключена (те же слова, на треть быстрее); с ней +49%.

Поверх векторов лемм: 2–4 слоя шириной 64–128, сотни килобайт. Векторы входа и выхода общие.
- **Задача:** не порождать следующее слово, а **выбрать среди кандидатов нашего поиска** с калиброванной уверенностью. Идея Jev (TypeSafe AI): типизированный выбор из заданного набора, вероятности вместо текста. Калибровка критична: все наши решения — пороги (запятая при 90%, запас для замены настоящего слова).
- **Оценка кандидата:** вектор контекста h · вектор леммы кандидата (близко к JEPA — сравнение в пространстве представлений) плюс грамматика формы. Считаются только найденные кандидаты, выходной слой на весь словарь не нужен.
- **Обучение на синтетике.** `typetext` и `swipesim` порождают тройки «контекст + кандидаты декодера + что человек имел в виду» на любом корпусе и при любом шуме нажатий или свайпа. Учится офлайн, на пользователе ничего не учится.
- **Место в поиске:** пересчёт найденных кандидатов (с запасом). Граница отсечения внутри поиска остаётся от пар лемм.
- **На телефоне:** вывод на Rust, несколько матричных умножений, доли–единицы миллисекунд на место. Для набора слово за словом подходят и рекуррентные схемы (RWKV, Mamba): состояние обновляется на каждое новое слово.

Порядок: лемматизация корпуса → векторы лемм → двухуровневая схема (замер) → трансформер-выбирающий (замер против неё).

Трансформер не заменяет двухуровневую схему, это два слоя разной скорости («быстрое и медленное мышление»):
- **пары лемм** работают внутри поиска: быстрая оценка с нижней границей на префикс, без неё нечем отсекать;
- **трансформер** точно выбирает из короткого списка, который поиск нашёл.

Векторы лемм у них общие, форму слова в обоих случаях выбирает грамматика.

### Единый граф предложения и текста (решено 30 сентября 2026)

Граф строится и дополняется постоянно. Все прочтения предложения и текста лежат в одном графе, неоднозначное не выбрасывается, а взвешивается. Правильное прочтение должно быть в графе всегда.
- **Слова и их разборы:** у слова все его прочтения (лемма + граммемы; «стали» — пять падежей существительного и глагол).
- **Связи:** «зависимое прочтение → главное прочтение, тип связи» — все, что допускает грамматика, с равными шансами. Грамматика выучена из разборов (`tools/graph_grammar.py`): правильная связь есть в графе для 99,95% слов, правильный разбор предложения целиком — в 99,8% предложений. Вероятности даёт ученик-разборщик (`tools/graph_parser.py`: наши векторы лемм, классы и граммемы, учитель — разборы Stanza), он ничего не выбрасывает, только упорядочивает.
- **Замер 30 сентября 2026** (14 тыс. отложенных предложений, эталон — разборы Stanza): разборщик по всему предложению ставит верное главное слово первым в 97,8% (с типом связи 97,0%), среди трёх первых — 99,93%, ошибка калибровки 0,24%; по мере набора (видит только слова слева, «главное впереди» — отдельный вариант) — 95,5% и 99,90%. 857 тыс. параметров, векторы лемм общие. На примерах: «увидел девушку с биноклем» — «с биноклем» к девушке 0,52 / к «увидел» 0,48; «отец бил сына, потому что он был пьян» — «он» = отец или сын, поровну; «мы стали друзьями» — глагол, «из стали делают» — существительное.
- **По мере набора:** новое слово добавляет свои прочтения и связи к предыдущим, «ждущие» слова (подлежащее без сказуемого) цепляются к нему — разборщик в режиме «слева направо». Когда предложение закончено, оно перечитывается разборщиком по всему предложению (это же вычитка).
- **Текст:** упоминания отдельно от сущностей; «упоминание → сущность» — все допустимые (род, число, одушевлённость) с вероятностями; факты — выводы с опорами (связи и упоминания), снимаются при пересмотре опоры.
- **Признаки — явные узлы:** «мужской род», «единственное число», «одушевлённое»… Согласование идёт через общий узел: «он → мужской род ← сын», «девочка → женский род ← побежала». Сейчас кандидаты местоимения уже подбираются по совпадению граммем, но граммемы узлами не стоят; явные узлы сделают каждое согласование видимым и объяснимым.
- **Клавиатура берёт из графа:** ожидаемую роль и падеж следующего слова, смысловую пару «главное → зависимое», границы клауз для запятых, «сказуемое или инфинитив» для -тся. Нынешний проход грамматики назад уходит.
  - Путь: граф — вход выбирающего. Каждое слово контекста получает из графа (`Context::graph`) шанс «ждёт главное впереди» и тип своей связи; выбирающий учится на них (признаки считаются тем же разборщиком по уже собранным данным `data/chooser2`), в Rust признаки берутся из `Context`. Честное ожидание: опыт с ролями от старой грамматики дал мало (log-loss 0,0732 → 0,0724) — на коротких фразах выбирающий и так видит, куда смотреть. Основная сила графа — в смысловых слоях (события, местоимения, текст), вычитке и запятых по границам клауз.
  - Разборщик в APK: ужать до 1–2 байт на число (сейчас 3,4 МБ), дописывание по одному слову (кеш ключей и значений внимания), а не пересчёт предложения. **Сделано 30 сентября:** веса в i8 со шкалой на строку (`--int8`, 0,9 МБ; главное слово то же у 99,94% слов), дописывание с кешем — 0,3 мс на слово вместо 1,4 мс на всё предложение, результат совпадает точно. В APK пока не кладётся: без решений, которые он меняет, это лишние 0,9 МБ.
  - **Первое решение из графа — подлежащее** (`graph_subject`, 30 сентября): существительное, которое может стоять в именительном («мать», «вода», у «машина» есть и родительный фамилии Машин), считается подлежащим, если граф говорит, что оно ждёт главное впереди. Согласование 65 → 80% («машина сбил» → «сбила»), но две ложные замены аккуратного набора: «у нэнси был → была», «я все время занята → занято». Граф знал, что слово **ждёт**, но не **как**: «время» ждёт «занята» как обстоятельство.
  - **Сделано (30 сентября): тип ожидаемой связи.** Разборщик по мере набора называет, как ждущее слово прицепится к главному впереди (`wait_rel`, верно в 96,6%; главное слово 95,4%, как раньше): «время» — обстоятельство 0,99, «у нэнси» — обстоятельство 0,99, «мать», «машина» — подлежащее ≈ 1. Подлежащим считается слово, ждущее **как подлежащее**, и его правило согласования весит по этой вероятности: при 0,67 («нос» перед «оторвали» может быть дополнением) штраф почти исчезает, при 0,96 («машина») остаётся сильным. Согласование 65,2 → 79,1%, -тся 78,3 → 78,7%, верных слов 94,37% (94,38), аккуратный набор не тронут. Включено (`graph_subject=1`), разборщик в APK: i8, 0,93 МБ, 0,3 мс на слово.
  - **Дальше — «кто ещё ждёт»:** у ждущего слова — вероятность, что его забрало каждое следующее слово (P(главное = t | ещё ждёт)). Тогда подлежащее находится через любые зависимые («мать Алекса впала», «мать моего старого друга впала»), а второе сказуемое наследует подлежащее первого («машина проехала по луже и всех нас обрызгала»).
  - **Составные узлы — устойчивые выражения.** Несколько слов внутри, снаружи одно слово своей части речи: неизменяемые («потому что», «несмотря на», «в течение» — союз, предлог), глагольные («впасть в кому», «иметь в виду» — сказуемое; изменяется главное слово внутри, от него и граммемы узла: «мать … впала в кому» согласуется через «впала»), именные («железная дорога»), наречные («как смоль», «сквозь розовые очки»). Составное прочтение лежит рядом с буквальным, у каждого свой вес. Источники: связи `fixed`/`flat`/`compound` в разборах Stanza, статистика последовательностей лемм (вместе, в одном порядке, почти без замен), фразеологизмы Викисловаря как проверка. Даёт клавиатуре предсказание выражения целиком, графу смыслов — одно событие или признак вместо буквальных слов, разборщику — меньше ошибок на устойчивых кусках.
  - **Знаки препинания — из графа, по правилам** (30 сентября). Знак — самостоятельная часть графа: у связи своё правило, где стоят её знаки (придаточное, «который», причастный и деепричастный обороты, обращение — запятые на границах; «а», «но» и соединённые предложения — перед союзом; однородные без союза — между; вводные и составные вводные «по его словам», «в частности» — вокруг; «…, сообщил он» — рамка; «?» — вопросительное слово в главной части). Отдельной модели запятых больше не нужно: она становится свойством связей (`tools/graph_marks.py`).
    - Разборщик читает знаки (`tools/parse_marks.py`: что стоит перед словом), при обучении часть их выбрасывается — он разбирает и текст без запятых. Длинные предложения: новости и Википедия (Stanza, до 40 слов), «Война и мир» — только проверка.
    - Замер: разборщик на «Войне и мире» (все предложения до 40 слов, эталон — Stanza) 87,6% со знаками, 84,3% без них (прежний, только на словах: 80,6% на предложениях до 12 слов). Запятые по правилам на верном графе: новости 92,8% верных, найдено 85,2%; «Война и мир» 87,9% и 85,9%. На нашем графе без запятых (новости): 81,9% и 69%, при уверенности графа ≥ 0,9 — 89,4% (найдено 34,5%). «?» по вопросительному слову — 90% верных на разговорных фразах; вопрос без вопросительного слова виден только по интонации. «!» и тире в диалоге — голос и стиль пишущего, не связь.
    - Находка: «вводное или нет» Stanza решает по запятым («очевидно» с запятыми — вводное в 98%, без — наречие). Разборщик учится решать это по смыслу — на тексте без запятых с ответом из текста с ними.
  - **Дальше — согласование по всему графу и тексту:** у каждой связи своё правило (подлежащее — число, род, лицо; определение — падеж, число, род; второе сказуемое — то же подлежащее; «который» — род и число своего слова; местоимение — мягко, через предложения; «я пришла» в начале текста — пишущий женского рода). Цена формы — по всем допустимым связям с их вероятностями, ни одна не выбирается окончательно. Тем же путём -тся/-ться: слово ждёт сказуемое или инфинитив.

### Слой событий: роли, вопросы, неявные факты (решено 30 сентября 2026)

Слои графа: **слова и разборы → связи (разборщик) → события, роли и неявные факты → текст (кореференция, сущности)**.
- **События — узлы (гиперграф через узлы, как в AMR):** «отец бил сына» — событие «бить»: кто? → отец, кого? → сын, когда? → прошлое. «Он был пьян» — событие-состояние «быть пьяным»: кто? → он, когда? → прошлое. «Потому что» — ребро «причина» между событиями.
- **Направление для человека — от главного к зависимому, с вопросом:** «бил → кого? → сына», «девушку → какую? → красивую». Вопрос — из типа связи и падежа зависимого. Грамматическая основа — особая взаимная пара «отец (что делал?) бил», она несёт согласование.
- **Неявные факты — узлы:** из граммем выбранного разбора — время (прошлое/настоящее/будущее), отрицание («не»), предположение («бы»), просьба (повелительное), род и число сказуемого (согласовано с подлежащим).
- **Неоднозначность сохраняется:** каждая альтернатива связи даёт альтернативную роль с той же вероятностью; «он» — два мира: «пьян был отец» / «пьян был сын».

### Главное направление: трансформер — учитель, граф — ученик

Решено 30 сентября 2026. Трансформер нужен не на телефоне, а как **учитель** общечеловеческого здравого смысла для графа (дистилляция знаний в явную структуру).
1. **Учитель офлайн:** трансформер на леммах и графах разбора, на большом корпусе связных текстов (классика в общественном достоянии, Википедия целыми статьями, новости, разговорные предложения), на видеокарте, любого размера.
2. **Перегонка:** вероятности учителя для возможных рёбер («пить → компот, дополнение», «зовут → Иван, имя», «его → герой, кореференция»), усреднённые по контекстам, становятся весами рёбер графа. Учитель обобщает на невиданные пары, простой подсчёт — нет.
3. **На телефоне — только граф:** строится для каждого текста с нуля; грамматика перечисляет допустимые рёбра с равными шансами, веса учителя выбирают. Решения объяснимы рёбрами, знание можно смотреть и править.
4. **Мерило:** нынешний выбирающий (маленький трансформер в `weigh`). Граф-ученик должен догнать «граф + трансформер»; если не догонит, трансформер остаётся тонкой добавкой.
- Риски: ошибки учителя запекаются (замер и правка), литературный язык ≠ переписка (учить на смеси), размер графа (явные сильные рёбра + сжатое остальное, как с векторами лемм).
- **Проверка понимания — граф целого произведения.** Граф явный, поэтому его можно спросить. Эталон вручную: 50–100 фактов «Войны и мира» (Пьер — сын графа Безухова, браки Пьера, дети князя Болконского, кто кого любил, кто где служил). Прогнать роман через граф, посчитать, какие рёбра он построил сам (полнота) и сколько ложных (точность); нарисовать граф персонажей. Трудности, ради которых это и проверка: одна сущность под многими именами («Наташа», «Наталья Ильинична», «графиня», «она»), французские страницы, факты через тома.

### Принцип: один источник знания, скомпилированные виды

Источник истины один — большой граф знаний офлайн (факты с источниками, правила, отзываемые выводы; события, время, родство; знания из Wikidata, ConceptNet и корпусов). Телефон получает **скомпилированные виды** этого графа — только нужное для набора, в компактной read-only форме (FST по номерам лемм, массивы, i8-веса, mmap), как сейчас корпуса компилируются в `bigrams.fst`. Граф текста на телефоне строится заново по текущему полю и ничего не хранит. Цепочка: нейросеть-учитель → явный граф → компиляция в массивы для телефона, на каждом шаге замер потерь. Корни: компиляция знаний (knowledge compilation), грамматики, скомпилированные в автоматы, Rete.

### Веса в структуре: граница нейронки на узле

Замер 30 сентября 2026: с выбирающим внутри поиска набор медленнее на 87% (граница «сколько нейронка может добавить слову» общая на все 50 тыс. лемм, поиск отсекает хуже), без его границы — на 31% (нейронка только переставляет найденное). Лечится весами в структуре словаря: на узлах основ — «коробка» векторов лемм ниже (минимум и максимум по каждой из 16 координат). Для места u = Wᵀh считается один раз, граница на узле — Σₖ max(uₖ·minₖ, uₖ·maxₖ), 16 умножений, и тесная: под «кош» лежит пара лемм, а не весь словарь. Хранить её удобно вместе с единым хранением «слово → номер»: узлу соответствует отрезок номеров, коробки — блоками по отрезкам (как блочные минимумы частот).

### Трансформер поверх графа зависимостей

Идея 30 сентября 2026. Предложение по мере набора раскладывается в граф: что к чему относится, с номером порядка. Трансформер работает поверх графа, а не просто над рядом слов.
1. **Роли слов контекста относительно набираемого:** главное слово, подлежащее, глагол клаузы, определение, предлог, прочее — их уже находит `gram::walk`. Плюс расстояние по графу. Подаются в модель как вложения, внимание получает сдвиг по типу ребра, и «запрос» сразу смотрит на главное слово («пить горячий ч…» → «пить»).
Уточнение: грамматика даёт **равные** шансы — строит весь граф допустимых связей и разборов, запрещённого в нём нет. Все предпочтения — у трансформера, он выбирает, куда идти. Для этого `gram::walk` должна перечислять все допустимые рёбра (к какому предыдущему слову набираемое может относиться и при каком разборе), а не искать одно главное слово; указатель трансформера выбирает только среди них. Промежуточный шаг: роли от нынешней грамматики (главное, глагол клаузы, определение, прочее) как вход, доверие к каждой роли трансформер учит сам.
2. **Граф с вероятностями:** не один разбор, а несколько с весами («стали», «за» — предлог или частица). Веса пересчитываются по мере набора, трансформер читает все разборы с их весами. Это переделка грамматики из «одного лучшего разбора» в распределение.
3. **Обратная связь от трансформера к графу.** Кроме оценок кандидатов трансформер выдаёт уточнённый граф: какой разбор и какое главное слово у каждого слова по смыслу всего предложения. Этот граф возвращается в грамматику и перевешивает ожидания для следующего слова, можно в 1–2 круга на место. Учится это на правильных графах от синтаксического анализатора (Stanza или UDPipe, SynTagRus) по обучающему корпусу — только при обучении, в клавиатуру он не идёт. Осторожность: петля может сама себя убеждать. Поэтому грамматика остаётся априорной, вероятности калиброваны, кругов немного, а запрещённое грамматикой нейронка не разрешает — она только перевешивает допустимое.

### Граф текста: связи между предложениями

Идея 30 сентября 2026. «…героя. Зовут его Иван. Имя героя — …». Грамматика связывает и между предложениями: «его» → «герой» (местоимение → допустимые предшественники по роду, числу, одушевлённости, с равными шансами), «зовут X» → связь «имя». В «имя героя —» она перечисляет всё, что граф связал с «героем» через «имя», а трансформер выбирает по смыслу. «Иван» попадает в ожидание места без всяких пар.
- Узлы — сущности текста (леммы с упоминаниями), рёбра — кореференция и отношения (имя, признак, принадлежность).
- Это чтение текущего поля, а не обучение: ничего не сохраняется и не переносится (принцип «не учиться молча»).
- Порядок: «кеш текста» (леммы и имена поля в ожидании места, с поправкой по давности) → связи местоимений → полный граф.
- Данные: нужны связные тексты (статьи, книги целиком — Tatoeba и Leipzig перемешаны по предложениям) и учитель кореференции для русского.
- Устройство графа:
  - **упоминания отдельно от сущностей:** «она», «Наташа», «графиня» — узлы-упоминания; связь «упоминание → сущность» — отзываемое убеждение со свидетельствами (имя, отчество, титул, соседние упоминания), ошибочная склейка правится одной связью;
  - **факт — убеждение с происхождением:** наблюдение, вывод по правилу (с опорами: сняли опору — вывод умирает), «сказал такой-то» — рассказчик и персонаж различаются;
  - **цитата — опора факта, а не приложение:** факт помнит абзац и упоминания, из которых извлечён; пересмотр кореференции («князь» — старый Болконский) сам снимает все факты, стоявшие на этом упоминании;
  - **время:** события — узлы (помолвка с датами и участниками) или у фактов интервалы, а не одно «текущее состояние»;
  - **законы по длине описания** («брат родителя — дядя», гипотезы псевдонимов); все изменения через одного писателя с политикой слияния (вывод не затирает наблюдение).

## 3а. Единое хранение: слово → номер → массивы

Всё о слове из одного пути, но без смешения в значении FST (замер: лемма в значении 9,1 → 12,6 МБ, отдельно +0,7 МБ; `docs/DESIGN.md`).
- **Автомат только слов** выдаёт номер слова, хвосты общие по максимуму (~3,2 МБ).
- **Массивы по номеру:** частота (энтропия ~1,8 бита на слово), грамматика (~1,2 бита при известных последних трёх буквах), лемма, заглавные и мат, ё.
- **Таблицы по номеру леммы** (векторы, класс смысла, основа) и по номеру грамматики.
- **Отсечение в поиске:** слова под узлом — непрерывный отрезок номеров, граница частоты — минимум на отрезке (блочный минимум).
- Оценка: частота и грамматика 4,5–5,5 МБ вместо 9,0, заглавные и лемма без отдельных карт.

Порядок решён 30 сентября 2026: сначала трансформер (качество), затем это (память), затем модель контекста по номерам лемм без того, что выучит трансформер. Перед переделкой — прототип размеров на Python.

**Сделано на ветке `unified-store` (30 сентября 2026):** частоты массивом по номеру (`index-builder --ranked`, `kbcore::store`, `dict.bin` рядом с `dict.fst`); грамматика осталась в автомате — массивом по номеру она дороже. Словарь 9,1 → 4,6 + 1,6 = 6,2 МБ. Лемма, заглавные и ё массивами по номеру не дешевле нынешних отдельных карт — не перенесены. Замеры — `docs/DESIGN.md`.

## 3б. Вычитка законченного предложения

Идея 30 сентября 2026. Окно из двух слов пересматривает только предыдущее слово. Когда предложение закончено (точка, «?», «!», пауза), каждое его слово можно перечитать с контекстом с обеих сторон: «здание школы сейчас строиться.» → «строится» (нет модального, есть подлежащее), «мать, должно быть, злиться.» → «злится» (вставка в запятых), «в течении дня» → «в течение». Сама исправлять только почти наверняка ошибочное — пару написаний (тся/ться, в/во, н/нн, -ение/-ении), где контекст с обеих сторон однозначен; ⌫ сразу после возвращает. Остальное — подчёркивание с исправлением в одно касание. Только текущее предложение, пока курсор в конце. Правило -тся/-ться сейчас 76% при правке в момент набора; вычитка должна поднять именно его и предлоги.

## 4. Корпуса

Веб систематически ошибается ровно в тех правилах, которые мы учим:
- «в течении», «не смотря на»;
- «тем не менее,» (71% веба);
- «подскажите пожалуйста» без запятых (51%);
- «по окончанию» (27% даже в новостях).

Правила, запятые и пары-путаницы нужно учить на вычитанных текстах (Leipzig news, книги, основной корпус НКРЯ), а где ошибается и корпус — задавать закрытыми списками.

## 6. Свайп на реальных жестах

Проверочная часть Yandex Cup 2023 (10 тыс. жестов), только для замеров. Данные вне репозитория, на них ничего не учится и не подбирается. Наша геометрия без контекста: 69,1% верных с первого места, у нейросети CleverKeys 85%.
- 19% слов теряются жёсткими геометрическими отсечками: радиус вокруг пути, начало и конец жеста.
- Следующий шаг: единый путь для геометрии — отсечка превращается в стоимость, и контекст может вытащить слово.
- Дальше: опорные точки на концах, штраф за направление, компенсация углов и быстрого старта. Проверка: подбор на одной половине набора, итог на другой.
- Если разрыв останется большим — маленький нейрокодировщик жеста (вероятности букв по кадрам) в наш обход словаря.
